# Senechal – backend

The backend of **Senechal**, the companion tool of a *King Arthur Pendragon* tabletop campaign. One Python process
(`server.py`) runs two things over a shared domain and data layer:

- an **aiohttp HTTP API** (`api/`) used by the Angular frontend (`../AngrySenechal2/`), plus a few static pages,
- a **Discord bot** (`senechal.py`) with commands for rolls, characters, the Winter Phase and the feast.

Both use the same PostgreSQL database, so a change of the schema or of the stored data format affects the bot and
the web UI alike.

## History

The project started in 2019 as a small helper bot when our DM went abroad for a year. At first it only handled dice
rolls and showed basic character information, all stored in JSON files. Later I switched to SQLite and stored more
data. When the bot moved to Heroku, I had to rewrite the database layer for PostgreSQL.

The backend then got a second process: a JSON API built with Django to serve the character data (not the ideal
choice, as I see now). The frontend was first written with jQuery and static HTML, but it was soon rewritten in
Angular. It worked well during the Covid pandemic. Development halted when we could play in person again.

The DM's second year abroad started a new development cycle. We moved from Heroku to self-hosting on a micro PC,
using an Apache proxy, duckdns.org and Let's Encrypt.

The third cycle was boosted by two factors: the DM went abroad again, and AI made it possible to implement ideas in
5–20 minutes. Most of the new code is now generated by Claude.

## Layout

| Path | Contents |
|------|----------|
| `server.py` | Entry point: API + bot in one process |
| `senechal.py` | Entry point of the bot alone |
| `message_handler.py` | Dispatcher of the bot commands |
| `commands/` | One file per bot command, each a `BaseCommand` subclass (check, opposed, attack, winter, feast, npc, …) |
| `events/` | Scheduled events (APScheduler) |
| `api/` | HTTP API: `app.py` (routes, Discord OAuth login), `views.py`, `feast_views.py`, `auth.py` |
| `bot_bridge.py` | Lets the web UI run dice rolls and commands in the user's Discord channel |
| `character.py`, `dicing.py`, `passions.py`, `permissions.py`, `winter_logic.py` | Rules and domain logic |
| `feast.py`, `feast_rules.py`, `feast.json`, `feast.yml` | Feast and seating plan |
| `database/` | Data layer: one handler per table (`base_table_handler.py`), raw `psycopg2`, parameterised SQL |
| `pdf/` | PDF character sheet generation (`fpdf2`) |
| `config.py` | Reads `config.yml` (optional, git-ignored), `senechal.yml` and `feast.json` |
| `characters.yml`, `npc.yml`, `config_base.yml` | Base data of characters and NPCs |
| `static/` | Static pages and assets served by the API |
| `tests/` | Unit and integration tests |
| `deploy/` | Deployment scripts (`deploy.sh`, `setup-systemd.sh`) |
| `documentation/` | Reviews, audits, the changelog and the task system |
| `pm/` | Project status, roadmap, decision log |

## Requirements

- Python 3.12
- PostgreSQL 14
- A Discord bot token ([register a bot](https://discord.com/developers/applications))

Install the dependencies (all versions are pinned) with `pip install -r requirements.txt`. Note that `fpdf2` must
not go below 2.8.9 (the PDF sheet embeds a variable font).

## Configuration

Secrets and settings come from environment variables (or the git-ignored `config.yml`). Never commit them.

| Variable | Meaning |
|----------|---------|
| `token` | Discord bot token (required, read at startup) |
| `DATABASE_URL` | PostgreSQL URL, including options such as `?sslmode=` (required; the connection is opened on first use and re-opened if it breaks) |
| `prefix` | Command prefix of the bot |
| `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET` | Discord OAuth login of the web UI |
| `CORS_ORIGINS` | Allowed origins of the API (optional) |
| `LOG_LEVEL` | `INFO` (default); `DEBUG` also shows command arguments |
| `TEST_DATABASE_URL` | Database for the integration tests (**wiped by the tests**) |

Do not log message contents, tokens or personal data.

## Running

```sh
python server.py      # API + bot
python senechal.py    # bot only
```

With Docker, use the `docker-compose.yml` in the workspace root (backend on port 8000, PostgreSQL on loopback).
`deploy/` contains scripts for a systemd based deployment.

## Tests

```sh
python -m unittest discover -s tests -p "*_test.py"
```

The database and PDF tests need `TEST_DATABASE_URL` and are skipped without it.

## Adding a bot command

1. Create a file in `commands/`, e.g. `commands/random_number.py`.
2. Define a class that inherits from `BaseCommand`. **The class name matters**: it becomes the command name in
   lower case, so `class Random` gives the command `random`.
3. In `__init__`, pass the description and the list of parameters to `super().__init__`.
4. Implement `async def handle(self, params, message, client)`.

```python
from commands.base_command import BaseCommand

class Random(BaseCommand):
    def __init__(self):
        description = "Generates a random number between two given numbers"
        params = ["lower", "upper"]
        super().__init__(description, params)

    async def handle(self, params, message, client):
        ...
```

See the existing commands for real examples. A scheduled event works the same way: a `BaseEvent` subclass in
`events/` (see `events/example_event.py`).
